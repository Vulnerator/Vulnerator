## Vulnerator 2.0 — 7.5.0 beta 3

**One record per device, and no licenses.**

### What's new
- **ACAS host ID.** .nessus files from Tenable Security Center carry a host ID that doesn't change when a device is
  renamed or gets a new IP.
  - Vulnerator now reads it from the host property set under **Ingest > ACAS Files > ACAS host ID tag** (`TAG` by
    default) and stores it with the hardware record.
  - A later scan with the same ID lands on the same record, and its new name is remembered as an alias.
  - Leave the tag empty to match by name only.
- **Merge hardware.** Tick two or more records that are the same device, for example `W01.Contoso.com` from ACAS and
  `W01.Contoso` typed into a checklist, then choose **Configuration Management > Hardware > Merge Ticked Hardware...**.
  - Findings, IP and MAC addresses, groups, software, ports, SCAP scores and submitted STIG releases move to the
    record you keep.
  - When both records have the same finding, the newest result is kept, along with its POA&M and mitigation links.
  - Blank fields on the kept record are filled from the others.
  - The other names become aliases, so later checklists or scans with those names land on the kept record.
  - A merge can't be undone. **Back up the database first** (ticked by default) copies the database file next to it.
- **New Hardware columns:** **Also Known As** (aliases) and **ACAS Host ID**.

### No licenses
- Vulnerator 2.0 needs no license key, and future versions won't add one.
  - The license storage is gone.
  - The add-on interface keeps its old license members, always empty, so add-ons built for it still load.
- The **Dashboards add-on is now open source (MIT)**. Its source and tests are in `AddOns/` in this repository, and
  CI builds it from source for every release.
- Anyone may fork Vulnerator and carry on their own work. The README and the project page say so.

### Tests
- **Checklist import test:**
  - the same host ID across a rename and a new IP gives one record and an alias
  - merging a checklist host into the ACAS record (findings, aliases, submitted releases), then a later checklist
    landing on the kept record
  - duplicate findings combined, keeping the newest along with its POA&M link
- **Dashboards and Metrics tests** now run in this repository's CI.
- **Add-on test:** add-ons get no licenses, and Dashboards has no license handling.
