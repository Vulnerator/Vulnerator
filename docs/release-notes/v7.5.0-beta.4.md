## Vulnerator 2.0 — 7.5.0 beta 4

**Devices are tracked by Vulnerator's own registry number instead of the ACAS TAG.**

### What's new
- **Registry numbers.** Every device in the Hardware list has a permanent Vulnerator number, such as `VUL-000123`.
  - It's shown in the new **Registry No.** column, which is on by default.
  - Existing records are numbered the first time this version opens the database.
  - New records get the next number automatically, whether they come from an import or are added by hand.
  - Numbers are never reused, even after a device is deleted.
- **Merge keeps the number.** When you merge records, the kept device keeps its registry number. The other devices'
  numbers are retired and point to it, and they're listed under **Also Known As** with the saved names.
- **Matching on import.** A scan or checklist lands on an existing device when its host name matches one of these:
  - the device's host name
  - a saved alias
  - the device's FQDN or NetBIOS name, but only when exactly one device matches

  For example, a checklist for `W01` lands on the ACAS record whose NetBIOS name is `W01`. IP and MAC addresses aren't
  used, because they change and get reused.

### Removed
- The ACAS host ID (the `TAG` host property and its setting) from beta 3 is no longer read or stored. Any IDs already
  saved are cleared when this version starts.

### Tests
- The checklist import test now checks:
  - every record has exactly one registry number
  - new devices get the next number, and numbers aren't reused after a delete
  - a checklist named by NetBIOS name or by FQDN lands on the existing record
  - a merge keeps the kept device's number and retires the other's
