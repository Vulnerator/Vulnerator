## Vulnerator 2.0 — 7.5.0 beta 1

**Pull checklists from STIG Manager.** Vulnerator can now sign in to your organization's STIG Manager server
(NUWCDIVNPT/stig-manager) and add checklists for the Assets you pick straight to the ingestion list.

### What's new
- **Ingest > Pull from STIG Manager...** Enter the STIG Manager API address, the OIDC provider address (Keycloak:
  `https://<server>/realms/<realm>`), the client ID and the scope (`openid stig-manager:collection:read` by default).
  Sign in, pick a Collection and its Assets, and choose **Add to ingestion list**. Then **Execute Ingestion** as usual.
- **Two ways to sign in.**
  - **Browser:** your browser opens the provider's sign-in page, so CAC works. It uses Authorization Code with PKCE and
    a redirect to `127.0.0.1` on this computer, with no administrator rights needed.
  - **Service account:** uses a client secret. You can have the secret remembered, encrypted for your Windows account.
- **Off by default.** Turn it on under **Settings > STIG Manager**. Only the two addresses you enter are contacted,
  over HTTPS. Plain HTTP is allowed only for this computer. Windows' proxy settings and certificate store are used.
- **Same import rules.** STIG Manager sends one zip with one CKL (or CKLB) per Asset and STIG. Vulnerator adds the zip
  like one picked from disk, so host matching, STIG releases, CCI mapping and markings all work as before.
- **Export problems are shown.** If STIG Manager could not export some Assets, Vulnerator lists them (from the zip's
  `_manifest.json`) and asks before adding the rest.

### Changed
- **Settings > Integrations** no longer shows a Licenses box or license status. Add-ons are listed with their
  settings. The bundled Dashboards add-on is free and unaffected.

### Good to know
- Checklists don't carry STIG Manager's review status (saved, submitted, accepted or rejected), so every result is
  imported.
- STIG Manager writes Informational, Unknown, Error and Not Selected results as Not Reviewed, and Fixed as Not a
  Finding.
- **For the STIG Manager administrator:**
  - For browser sign-in, register a public client with PKCE (S256) and the redirect `http://127.0.0.1:<port>/`.
  - For a service account, register a confidential client with client credentials.
  - Grant the account `stig-manager:collection:read` and access to each Collection.

### Tests
- New `Test-StigManager.ps1` runs against a fake STIG Manager server on 127.0.0.1. It covers:
  - discovery, service-account sign-in and browser sign-in with PKCE (including refused and timed-out sign-ins)
  - Collections, Assets, the archive download and its manifest errors
  - the address rules, the RFC 7636 test vector and the encrypted secret
- The checklist import test now also imports a synthetic CKL in STIG Manager's export format. It checks statuses,
  release, finding details and comments.
