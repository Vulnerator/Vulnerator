## Vulnerator 2.0 — 7.5.0

**One record per device, checklists straight from STIG Manager, and no licenses.**

### One record per device
- **Registry numbers.** Every device gets a permanent Vulnerator number, such as `VUL-000123`, shown in the
  **Registry No.** column.
  - Existing records are numbered the first time this version opens the database.
  - Numbers are never reused, even after a device is deleted.
- **Matching on import.** A scan or checklist lands on an existing device when its host name matches the device's host
  name, one of its other names, its FQDN or its NetBIOS name (FQDN and NetBIOS only when exactly one device matches).
  IP and MAC addresses aren't used, because they change and get reused.
- **Merge.** Tick the records that are the same device, for example `W01.Contoso.com` from ACAS and `W01.Contoso` typed
  into a checklist, then choose **Configuration Management > Hardware > Merge Ticked Hardware...**.
  - Findings, addresses, groups, software, ports, SCAP scores and submitted STIG releases move to the kept record.
  - When both records have the same finding, the newest result is kept, along with its POA&M and mitigation links.
  - The other names are remembered, and the kept device keeps its registry number. The other device's number now
    points to it.
  - **Back up the database first** (ticked by default) keeps a copy of the database file.
- **Find and other names.**
  - A Find box above the Hardware list searches names, other names, FQDN, NetBIOS name, OS, IP address and registry
    numbers (`VUL-000123` or `123`).
  - The side panel shows a device's registry number and other names. **Add Name** saves a name so later imports with
    it land on the device; **Remove** forgets a wrong one.
- **Hardware columns.** **Columns...** shows or hides Registry No., Operating System, Last ACAS Scan,
  Last Checklist / SCAP, Last Scan, Scan Sources, Groups, Role, Manufacturer, Model, Serial Number, Virtual,
  Lifecycle Status and Also Known As.

### Pull from STIG Manager
- **Ingest > Pull from STIG Manager...** signs in to your organization's STIG Manager server, either through the browser
  (CAC works, no admin rights needed) or as a service account.
- Pick a Collection and its Assets. Their checklists are added to the ingestion list and imported with the normal
  rules.
- It's off by default; turn it on under **Settings > STIG Manager**. Only the addresses you enter are contacted, over
  HTTPS.

### Dashboards 1.2.0
- **IAVMs** list the titles of the open findings behind each IAVM.
- **Coverage** shows each device's operating system and counts records with the same short host name as one device.
  Under **Device matching** you can link records or keep a match separate.

### No licenses
- Vulnerator 2.0 needs no license key, and future versions won't add one. The license storage is removed.
- The Dashboards add-on is now open source (MIT). Its source and tests are in `AddOns/` in this repository, and each
  release builds it from source.
- Anyone may fork Vulnerator and carry on their own work.

### Upgrading from 7.4.0
- Open your existing database as usual. Registry numbers are added on the first start.
- Nothing else in the database changes until you merge records or add names.
